# ADR-0003: TUI 技术路线

- 状态: Accepted
- 日期: 2026-04-08

## 背景

Claude Code 的交互体验高度依赖终端 UI。Clawin 需要保留公开交互语义，但不应试图在 Rust 中复制 React/Ink 的实现方式。

## 决策

Clawin 的 TUI 技术路线固定为:

- 渲染层: `ratatui`
- 终端与事件层: `crossterm`
- UI 组织方式: 显式状态机 + 组件树，而不是虚拟 DOM

保留以下对标原则:

- 屏幕流转与用户可见行为对齐上游
- 快捷键、焦点切换、中断语义、消息呈现顺序对齐上游
- 非交互模式不得依赖 TUI 组件

不追求以下事项:

- 不追求内部实现形态与 Ink 一致
- 不追求逐组件名称或目录结构对齐

## 后果

- 优点: 选型成熟，三平台终端支持较稳，生态足够成熟
- 成本: 某些复杂布局和流式更新需要自己维护更多状态
- 风险: Windows 终端差异需要尽早验证，不可等到收尾阶段
