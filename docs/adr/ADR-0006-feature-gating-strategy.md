# ADR-0006: Feature Gating 策略

- 状态: Accepted
- 日期: 2026-04-08

## 背景

上游 `2.1.88` 在大量子系统中使用 `feature(...)` 和产品内开关来裁剪实现。Rust 版本若直接复制这种模式，会把上游内部实验分支一并引入，破坏 V1 的范围控制。

## 决策

Clawin 的 feature gating 分三层:

- 编译期 gating
  - 用 Cargo feature 控制真正的可选编译单元
  - 仅用于平台专属能力、调试工具、实验性内部开发能力
- 运行期 capability
  - 用显式 capability/config 判断公开能力是否可用
  - 适用于用户环境差异，例如终端能力、可用依赖、MCP 连接状态
- 产品范围控制
  - 不在 V1 范围内的上游分支不进入默认实现，也不为了“对齐目录”而保留死代码

固定规则:

- 公开包 V1 必需能力不能藏在默认关闭的 Cargo feature 后面
- 任何新 feature 都必须说明其类型、默认值、目标用户和测试方式
- 若 feature 对用户可见行为造成偏离，必须分配差异 ID 或补充 ADR

## 后果

- 优点: 边界更清晰，避免把上游内部试验开关带进主产品
- 成本: 需要更明确地区分“公开行为”与“实现裁剪”
- 影响: 迁移时必须先判断一个上游 feature 是否属于 V1 公开包能力
